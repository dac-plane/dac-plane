# Pre-implementation architecture review

- Review date: 2026-10-15
- Confidence: high for the ownership and initial application boundaries; moderate for storage and
  provider choices until failure and conformance tests exist
- Decision: **proceed with the corrected baseline; do not select a production runtime or environment by
  assumption**

## Conclusion

The direction is coherent: `dac-plane` is the authoritative delegated-work lifecycle, not another agent
runtime, model gateway, sandbox platform or generic workflow engine. Runtimes reason and execute their
native sessions. Environment providers own workspace and process resources. The product owns the task
outcome, attempt history, attention and decisions, budgets, evidence, audit and result review across
those providers.

The first diagram overstated the deployment design by drawing the API, dispatcher and reconciler as
separate applications. The corrected baseline starts as one modular control-plane application plus two
stores. Provider systems remain external. This is the smallest architecture that can prove the product
semantics without creating an accidental distributed system.

The later static Plane-Bot investigation supports these boundaries with shipped-system evidence for
versioned control ports, replayable observation streams, provider-resource bindings, scoped action
authority, synchronous enforcement hooks, spend authorization and fenced artifact admission. ADR-0003
adopts those semantics without adopting the vendor's topology, API surface, transports or provider
implementations.

## Corrections made by this review

1. Combined API, lifecycle, outbox dispatch, reconciliation and adapter orchestration into one initial
   control-plane application. A future process split now requires evidence and an ADR.
2. Added explicit provider-to-product return paths for normalized events, attention, results, resource
   state and enforcement receipts. Commands without an observed outcome are not completion.
3. Made action enforcement mandatory for governed actions while leaving its mechanism replaceable. It
   may be a qualified runtime hook or a dedicated policy/tool/secret gateway.
4. Marked the local environment adapter as development-only. It is not a production isolation claim.
5. Removed named runtime products from the architecture. No production runtime is selected yet.
6. Clarified artifact ownership: bytes may be external, but identity, digest, classification,
   provenance and result association are authoritative product records.
7. Separated the active implementation baseline from the historical specification and qualification
   material under `architecture-explore/`.

## Invariants for implementation

- Only the control-plane application writes authoritative product records.
- Every mutating surface command is authenticated, authorized, idempotent and version checked.
- A state transition and its outbox entry commit atomically.
- Delivery is at least once; commands and provider events carry stable identities and consumers dedupe.
- Leases are fenced. A stale lease holder cannot mutate an Attempt or acknowledge a Decision.
- Cancellation is an intent until the runtime and environment stop are observed or reconciled.
- Unknown external outcomes enter an explicit uncertain state; they are never retried as if no effect
  occurred.
- Provider events are authenticated and bound to tenant, Attempt, provider operation and sequence or
  deduplication identity before they affect product state.
- Provider peers select one mutually supported protocol version and capability set before work begins;
  malformed frames, incompatible versions and missing required capabilities fail with typed outcomes
  rather than implicit fallback or downgrade.
- Event cursors preserve generation, revision, replay, tombstone and rehydration semantics. Cursor
  acknowledgement is ingestion progress, not lifecycle completion.
- Governed actions use scoped, short-lived authority and produce an enforcement receipt or denial.
- After hook rewriting, the dispatch transaction revalidates the effective action's authority, scope,
  expiry, revocation, policy generation and permission ceiling. It atomically records authority use,
  audit, durable event, provider operation and outbox, including one-time retirement. A failed predicate
  or hook denial records an operation-bound denial and safe audit/event evidence but creates no
  executable operation or dispatch outbox; an indeterminate provider outcome does not restore consumed
  authority.
- Governed effects require a valid affirmative pre-action hook response. Failures before durable
  dispatch produce no executable operation or external effect; loss after dispatch enters
  reconciliation instead of retrying the effect.
- Audit records use classified redactions, digests or safe evidence references and never persist
  provider credentials, secret-bearing fields or unrestricted raw action payloads.
- Shadow harnesses may record comparison evidence but cannot mutate authoritative state or perform
  governed external effects.
- Spend challenges are replay protected and produce durable receipts without replacing authoritative
  Budget reservation and consumption.
- Artifact bytes are integrity checked; metadata and result lineage are committed by the product.
- Artifact registration requires a verified committed manifest; retry and fenced outcomes create no
  Artifact or ResultRevision.
- Stateful actions carry observation preconditions, reject stale state and execute serially per
  controlled resource.

## Contract-freeze gate

The exploration prototypes are useful input, not a complete implementation contract. In particular,
the PostgreSQL prototype has no authoritative Budget, ResultRevision or ResultReview tables even though
the target product model owns those records. Before the executable service expands beyond the first
vertical slice, the active Go contracts and migration must define:

1. identifiers, tenant ownership, versions and state transitions for all nine product records;
2. budget reservation, consumption, release and ceiling behavior before and during execution;
3. immutable result revisions and reviews bound to an exact revision and reviewer authority;
4. adapter commands, normalized events, cancellation acknowledgement and replay/deduplication rules;
5. artifact upload, digest verification, provenance and registration ordering; and
6. tenant/principal identity mapping and scoped provider credentials.

Those contracts must also implement the provider-neutral families adopted by
[ADR-0003](../adr/0003-provider-contract-semantics.md): `ControlFrame`, `EventCursor`, execution bindings,
environment and harness lifecycle, `AuthorityGrant`, `AuthorityUse`, `HookRequest`, `HookResponse`,
`SpendChallenge`, `ArtifactCommitOutcome` and `ActionPrecondition`. The Go contracts and JSON Schema
2020-12 documents must agree on required identities, enums, failure outcomes and replay behavior before
persistence begins.

The next implementation task should therefore be the active domain contract, migration and deterministic
simulator tests for one end-to-end lifecycle—not an HTTP framework, Kubernetes deployment or real agent
integration.

M1 requires full contract-and-simulator parity for these behaviors. It does not qualify a production
runtime, environment, enforcement mechanism, credential ceremony, artifact store or computer-use
provider.

## Open decisions that do not block the simulator slice

| Decision | Current position | Evidence required before selection |
|---|---|---|
| Production agent runtime | Open | Adapter conformance for events, attention, cancellation, recovery and result export |
| Production environment provider | Open | Isolation, lifecycle, cleanup, credential and failure-reconciliation tests |
| Artifact byte store | Open | Scoped access, immutable writes, digest validation, retention and deletion behavior |
| Credential ceremony | Open | Challenge binding, replay resistance, expiry, revocation and receipt verification |
| Computer-use integration | Open | Action scoping, stale-precondition rejection, serialization and evidence capture |
| Deployment substrate | Open | Operational requirements; Kubernetes is not assumed |
| Workflow engine | Not adopted | Add only if SQL/outbox failure injection proves insufficient |
| First-party web workspace | Later | The public API and lifecycle slice must work without it |

## Primary-source checks

- The [C4 container definition](https://c4model.com/abstractions/container) treats a container as a
  running application or data store, so internal modules should not be drawn as containers before a
  runtime boundary exists.
- The [transactional outbox pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)
  addresses database/event dual writes but explicitly requires idempotent handling of duplicate
  deliveries.
- PostgreSQL documents `SKIP LOCKED` as useful for avoiding lock contention with queue-like tables in
  [`SELECT`](https://www.postgresql.org/docs/current/sql-select.html); it does not remove the need for
  lease fencing, retries or reconciliation.
- The [CloudEvents specification](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md)
  provides a useful interoperable event envelope, but domain sequencing, authentication and tenant
  binding remain product responsibilities.
- The optional [CloudEvents sequence extension](https://github.com/cloudevents/spec/blob/main/cloudevents/extensions/sequence.md)
  orders events within a source but does not define generations, revisions, completeness, tombstones or
  rehydration, so it cannot replace the product's `EventCursor` contract.
- NIST's [agent identity and authorization guidance](https://www.nist.gov/blogs/cybersecurity-insights/back-future-why-agentic-ai-needs-strong-identity-foundation)
  supports unique agent identities, tightly scoped and short-lived authority, and avoiding shared static
  credentials.
- Go's [`context` model](https://go.dev/blog/context) supports request-scoped cancellation propagation;
  durable cancellation acknowledgement still belongs in product state.

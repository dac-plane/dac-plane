# dac-plane v0.1.0

This is the first release of dac-plane, a control plane for delegating work to AI agents. You submit a task, an agent works on it in a sandbox, and dac-plane keeps the durable record: what was asked, what was approved, what was spent, what came back and who reviewed it. The agent runtime and the sandbox stay replaceable.

The highlights of this release are:

- Delegate work to an agent and review its results, with a durable record of every step
- Keep a person in control with approvals, budgets and cancellation that proves the work stopped
- Run Codex with its commands contained in an E2B sandbox
- Integrate another provider from outside this repository with the adapter kit
- Verify what you run with signed tags, provenance and SBOMs

This release is for self-hosted pilots. It makes no availability, throughput, cost or production claim, and no support objective has been established. Read [Known limits](#known-limits) before you rely on it.

## Delegating work

### Tasks, attempts and reviews

A task records the work you asked for. Each try at it is an attempt, and an attempt's result becomes a revision that a person can review and accept or send back for rework. Every change is recorded in an audit trail, and the records survive a restart of any process.

Everything is served through Surface API v1, with [an OpenAPI document](https://github.com/dac-plane/dac-plane/blob/v0.1.0/contracts/openapi/surface-v1.json) and a stream of events you can resume from a cursor. Callers authenticate through your OIDC issuer, and each tenant sees only its own work.

### Approvals

When an agent needs permission, for example to run a command, the task waits and raises an attention request for its owner to decide. An open request survives a restart of the control plane. If the runtime that asked is lost, the request ends instead of leaving the task waiting forever.

### Budgets

Each attempt holds a reservation against a budget, and the reservation is released when the attempt ends, so a failed or cancelled attempt does not keep its budget tied up.

### Cancellation that proves the work stopped

A cancelled task finishes only after the runtime and the environment have each been observed to stop. In live qualification, the agent's command was confirmed gone and E2B was asked directly whether the sandbox still existed. This held when an adapter was down, restarted or lost a message during the cancellation.

## Running agents

### Codex in E2B sandboxes

Codex app-server 0.165.0 runs the agent, and its commands execute in the E2B sandbox assigned to the attempt. Stopping the sandbox ends the work. In live qualification, a search from inside the sandbox found no model, attach, token or E2B secret, and the sandbox could not reach the model endpoint or `1.1.1.1`.

See [ADR-0016](https://github.com/dac-plane/dac-plane/blob/v0.1.0/docs/adr/0016-run-agent-commands-inside-the-environment.md) for the design.

### Artifacts in S3-compatible storage

Files an agent produces are read from the sandbox and stored through an S3 adapter, with exact bytes. The bundled profile uses SeaweedFS 4.51.

## Building on dac-plane

### Adapter kit

Providers connect through separate adapter processes, so you can add one without changing the control plane. The Go adapter kit handles the connection and the ControlFrame protocol, and its conformance suite checks your adapter's behavior. [`examples/minimal`](https://github.com/dac-plane/dac-plane/tree/v0.1.0/adapterkit/examples/minimal) is a complete adapter that passes the suite.

```sh
go get github.com/dac-plane/dac-plane/adapterkit@v0.1.0
```

While the kit is v0, a minor version may change its Go API.

## Running dac-plane

### Deployment

The control plane is a non-root distroless image, with an explicit migration step and a reference Compose stack. Follow [the deployment guide](https://github.com/dac-plane/dac-plane/blob/v0.1.0/deploy/compose/README.md) and set `DAC_PLANE_IMAGE` to the digest from the release manifest.

### Verifying what you pull

Tags are signed, images are reproducible and carry provenance and an SBOM, and each image's scan results are attached to this release. The release gate stops on a fixable HIGH or CRITICAL finding, so unfixed and lower findings may appear in those results.

```sh
gh attestation verify oci://ghcr.io/dac-plane/dac-plane@sha256:DIGEST --repo dac-plane/dac-plane
docker run --rm ghcr.io/dac-plane/dac-plane@sha256:DIGEST version
```

## Upgrading

This is the first release, so there is no supported upgrade into it. A database created by an earlier development build is not supported.

Later releases follow ADR-0011: roll every `serve` replica to the new image while the schema stays unchanged, confirm no old process or adapter connection remains, then run the new image's `migrate up`.

To roll back before a migration, restore the old image. After one, an old binary may return only if the database is inside its serving range, which `dac-plane migrate status` shows. `migrate down-to` refuses when a downgrade would discard durable evidence. Treat that as a stop, and do not delete data to get past it.

## Known limits

- **The published images have not run against live providers.** They pass the build, scan and clean-room checks on both architectures. Live evidence comes from local arm64 builds of an earlier commit, so amd64 has none. Qualify the digests you deploy before relying on them.
- **A provision can stall.** If E2B takes more than 45 seconds to answer a create, or the reply is lost, and the adapter cannot find the sandbox, the attempt stays in `provisioning` until someone cancels the task. This was seen once in about 18 live provisions. Cancelling works but can be slow: until the adapter can rule out a late create, it waits for the sandbox lifetime plus 5 minutes (`DAC_E2B_SANDBOX_TIMEOUT`, 15 minutes in the reference overlay, so up to 20 minutes).
- **Other providers are unqualified.** Only Codex, E2B Cloud and the bundled SeaweedFS have run live, and only together. E2B Cloud's own build cannot be pinned.
- **Codex notices.** `codex-app-server` ships with OpenAI's license and notice. Its archive has no notices for the Rust crates compiled into it, so they are not reproduced.

The [provider qualification note](https://github.com/dac-plane/dac-plane/blob/v0.1.0/docs/architecture/provider-qualification-75.md) and [release evidence](https://github.com/dac-plane/dac-plane/blob/v0.1.0/docs/architecture/release-95.md) record what was and was not observed.

## Compatibility

`release-manifest.json`, attached to this release, is the authoritative list of image digests. Deploy by digest.

| Component | Version |
|---|---|
| Images | `ghcr.io/dac-plane/{dac-plane,dac-codex-adapter,dac-e2b-adapter,dac-s3-adapter}`, `v0.1.0` |
| Architectures | `linux/amd64`, `linux/arm64` |
| Adapter kit | `v0.1.0` |
| Database schema | Serves 13 to 15. `migrate up` takes a database to 15. |
| Surface API | v1, OpenAPI document 1.0.0 |
| ControlFrame protocol | 1 |
| PostgreSQL | 16 |
| Codex | app-server and CLI 0.165.0 |
| E2B | E2B Cloud. Build the sandbox template with `just build-e2b-codex-template`. |
| Artifact store | SeaweedFS 4.51 |

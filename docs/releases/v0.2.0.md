# dac-plane v0.2.0

This release is the first one a running deployment upgrades to. It adds a provisioning command for a tenant's authority policy, fixes an adapter kit race that could drop every operation on a connection, and ships the overlay, runbook and guide that came out of operating the first pilot. The highlights of this release are:

- Set a tenant's authority policy with `provision set-policy`, with no direct database update
- Deploy a production-shaped pilot with Keycloak, Codex, E2B and SeaweedFS from a Compose overlay and a numbered runbook
- Follow a published user guide to run, deploy, operate and integrate dac-plane
- Keep an adapter's connection when a stream ends while one of its events is being written
- Upgrade from v0.1.0 along a path that is tested on every change

This release is for self-hosted pilots. It makes no availability, throughput, cost or production claim, and no support objective has been established. Read [Known limits](#known-limits) before you rely on it.

## Delegating work

### Setting the authority policy

A tenant's policy decides which actions an agent may take outright, which wait for a person and which are refused. v0.1.0 had no command for it, so the pilot set its first policy by updating the database directly. `provision set-policy` now replaces the whole policy, advances its generation and records the change with every other provisioning change.

```sh
dac-plane provision set-policy -tenant TENANT -settings '{"process.exec":"ask"}' -ceiling '{"process.exec":"ask"}'
```

Setting the same policy again changes nothing. If someone else changed the policy between the read and the write, the command reports a conflict instead of overwriting it. See [the command line reference](https://dac-plane.github.io/dac-plane/reference/cli/).

## Building on dac-plane

### Adapter kit v0.1.1

Ending a stream while one of its events was being written closed the adapter's whole WebSocket connection, and with it every operation on that session. Events are now written under the session's context, and ending a stream waits for the event it is writing.

A failed token fetch no longer always reads as refused credentials. The kit now tells a refusal apart from an issuer that could not be reached or answered with a server error, so an issuer restart does not look like a wrong secret.

```sh
go get github.com/dac-plane/dac-plane/adapterkit@v0.1.1
```

The Go API is unchanged. The three bundled adapters are built with this kit.

## Running dac-plane

### A pilot deployment

`compose.pilot.yaml` and `compose.keycloak.yaml` deploy the release images by digest with Codex, E2B, SeaweedFS behind HAProxy and Keycloak as the issuer. `generate-pilot-config.sh` and `configure-pilot.sh` create the configuration, realm and provisioning. They are in this release's Compose bundle. In v0.1.0 they had to be taken from `main`.

The overlay and scripts still pin the v0.1.0 digests and set the first policy by a direct update. To pilot v0.2.0, set the image variables to the digests in this release's manifest.

### User guide

[The user guide](https://dac-plane.github.io/dac-plane/) covers a first task on the simulator stack, the concepts, deployment and operation step by step, the Surface API and writing an adapter. Its configuration and command line references are checked against the code.

## Upgrading

Follow ADR-0011, in this order:

1. Roll every `serve` replica and every adapter to the v0.2.0 digests while the schema stays at 15. v0.2.0 serves schema 13 to 16.
2. Confirm that no v0.1.0 process or adapter connection remains.
3. Run the v0.2.0 image's `migrate up`, which takes the database to 16.

Before step 3, roll back by restoring the v0.1.0 digests. After it, v0.1.0 refuses to serve, because it serves only up to 15. `migrate down-to 15` returns the database to its range unless a `set-policy` change has been recorded. In that case it refuses, because the downgrade would discard that record. Treat the refusal as a stop.

This path runs in CI on every pull request: a v0.1.0 deployment, pulled by digest, is rolled and migrated with a task in flight, and `set-policy` is applied afterwards.

### Breaking changes

None.

### Notable changes

- Schema 16 lets a provisioning change record `set_policy`. It adds no table or column.
- The images are built with Go 1.27.4, and the Go dependencies and base images are updated.

## Security fixes

- **GO-2026-6859.** Go 1.27.3's `net/http` could crash an HTTP/1 server through a race on a `MaxBytesReader` header. v0.1.0 was built with an affected toolchain. Upgrade to these images.

## Known limits

The limits in [the v0.1.0 notes](v0.1.0.md#known-limits) still apply, except as [the release evidence](../architecture/release-134.md) records for live qualification of this release's images.

- **A provision can stall.** It was seen again in the live run before this release. See the v0.1.0 notes for what it looks like and how cancelling behaves.
- **The pilot has not been upgraded.** The upgrade is tested with simulators in CI. No deployment with real providers has yet been upgraded from v0.1.0.

# dac-plane v0.5.0

This release lets a person answer an agent's question in words, and lets a surface list tasks and providers without keeping its own index. An agent that asks a question now reaches a person as text, and the person's answer reaches the agent as text; a surface can list a principal's tasks page by page and the providers it may name. The highlights of this release are:

- Read the question a runtime asked and answer it in words, with the answer's text delivered to the runtime and checked against its recorded digest
- Ask a question through Codex: its `request_user_input` tool now reaches a person
- List the tasks a principal can read, newest first, page by page, and the runtime and environment providers a surface may name
- Give a provider a name when you register it, so a person can choose between two

This release is for self-hosted pilots. It makes no availability, throughput, cost or production claim, and no support objective has been established. Read [Known limits](#known-limits) before you rely on it.

## Delegating work

### Answer a question in words

A runtime that asks a person something raises an attention request of kind `question`, and can now carry the prompts: an `id`, a header, the text and optional options for each. `GET /attention/{attention}/question` returns them to the task's owner only; everyone else, a tenant reader included, gets `404`. A decision of kind `answer` carries `answer`, one string per prompt id, and `answer_digest`, the SHA-256 of that answer in the canonical form of RFC 8785. dac-plane refuses an answer whose digest differs, that leaves a prompt unanswered, or that picks something that is not one of a prompt's options, and it hands the runtime the text. See [Questions](https://dac-plane.github.io/dac-plane/use/surface-api/#questions).

### List tasks and providers

`GET /tasks` lists the tasks the principal may read, newest first, with `state` and `agent` filters and `limit` and `cursor` paging. A task submitted between two pages is neither skipped nor repeated, and a task whose state changes does not move. `GET /providers` lists the tenant's runtime and environment providers with an optional name and, for a runtime, its harness mode. Nothing operator-only is listed: no adapter identity, endpoint or credential. See [Listing tasks](https://dac-plane.github.io/dac-plane/use/surface-api/#listing-tasks) and [Providers](https://dac-plane.github.io/dac-plane/use/surface-api/#providers).

## Running agents

### Questions through Codex

The Codex adapter turns Codex's `request_user_input` request into a question and replies with the answers. It starts every thread with `features.default_mode_request_user_input`, without which Codex 0.165.0 answers the tool with "unavailable in Default mode". It declines a prompt marked secret, and a request outside the question limits, rather than store or truncate it.

## Building on dac-plane

### Adapter kit v0.5.0

`attention.requested` accepts an optional `question`, and a `steer_turn` for an answer decision carries `answer`. Both are optional: an adapter that sends no question keeps working, and a request without question text is still answered by digest alone. A control plane older than v0.5.0 refuses an `attention.requested` entry that carries `question`, so roll the control plane before the adapters that send it. See the [adapter guide](https://dac-plane.github.io/dac-plane/extend/adapters/).

```sh
go get github.com/dac-plane/dac-plane/adapterkit@latest
```

## Running dac-plane

### Provider names

`dac-plane provision register-provider` takes `-name`, one line of at most 100 characters. Registering a provider again without `-name` keeps the name it has.

## Upgrading

Follow ADR-0011. The schema moves from 18 to 20 with two additive migrations (question and answer text, then provider names and a task listing index):

1. Roll every `serve` replica to the v0.5.0 digest while the database is still at 18. v0.5.0 serves 13 to 20.
2. Run `dac-plane migrate up` with the v0.5.0 image.
3. Roll the adapters to the v0.5.0 digests. Roll the control plane first: see Adapter kit v0.5.0.

Between steps 1 and 2 a question is raised without its text, reading it answers `404`, an answer with text is refused with `503 not-migrated`, names cannot be set, and `GET /tasks` works without its index. Nothing already running is affected.

Roll back before step 2 by restoring the v0.4.0 digests; nothing in the database changes. After step 2 the v0.4.0 binary refuses the schema, so roll forward.

### Breaking changes

None. The Surface API stays v1; its document moves to 1.4.0 with additions only.

### Notable changes

- A question that has stored text must be answered with text. A client that answers by digest alone, as the reference application did, is refused with `422` for such a question and keeps working for a question that has none.
- The adapter kit is now versioned with the release: `vX.Y.Z` and `adapterkit/vX.Y.Z` are tagged together, even when the kit did not change.
- The GitHub Release lists only `release-manifest.json` and the compose and contracts bundles. Each image's scan, SBOM and provenance are no longer attached; the attestations are in GitHub's attestation store and the registry, and `gh attestation verify` checks them.

### Deprecated features

None.

### Removed features

None.

## Known limits

The limits in [the v0.4.0 notes](v0.4.0.md#known-limits) still apply.

- **The question flow was observed live once, on one runtime.** `just qualify-codex-question` passed against Codex app-server 0.165.0 and Camer's `deepseek-v4-flash-0731`: the model asked, a person answered in words, and the file the model wrote held the answer. `request_user_input` is experimental in Codex, and a Codex version that changes it can stop questions from being asked.
- **A secret prompt is declined.** An answer to it would be stored, so the adapter replies to Codex with no answers instead.
- **A control plane older than v0.5.0 refuses a question's text.** Nothing enforces the rollout order for this field; a negotiated capability would ([#170](https://github.com/dac-plane/dac-plane/issues/170)).
- **Whether an adapter is connected is not listed.** A connection lives in one replica's memory, so no replica can answer for the others; the harness mode is the readiness a surface sees.
- **A task page reads each task on its own.** A page holds at most 200 tasks; a join is the next step if a tenant's pages prove slow.
- **This is the first release cut from a release-please pull request.** The path was not rehearsed before it.

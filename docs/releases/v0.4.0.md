# dac-plane v0.4.0

This release lets a surface show what an agent produced. A result revision has always listed its artifacts by identifier; a surface can now read each artifact's record and download its bytes through the Surface API, so a reviewer reads the work before accepting it. The highlights of this release are:

- Read an artifact's kind, media type, size, digest, producer and commit time with `GET /tasks/{task}/artifacts/{artifact}`
- Download its bytes with `GET /tasks/{task}/artifacts/{artifact}/content`, checked against the recorded length and digest before the download completes
- Keep the artifact store unpublished: dac-plane fetches a short-lived presigned read from the store and relays it, and surfaces never reach the store

This release is for self-hosted pilots. It makes no availability, throughput, cost or production claim, and no support objective has been established. Read [Known limits](#known-limits) before you rely on it.

## Delegating work

### Read and download a result's artifacts

`GET /tasks/{task}/artifacts/{artifact}` returns the admitted record of an artifact of that task. `GET /tasks/{task}/artifacts/{artifact}/content` streams its bytes as an attachment, with the admitted media type, length and `Repr-Digest`, `X-Content-Type-Options: nosniff` and a sandboxing `Content-Security-Policy`, because the bytes are agent output. A store answer whose length differs from the record is refused before any byte is sent, and bytes whose digest differs abort the response, so no complete body with the wrong digest is delivered. Both are readable by whoever may read the task ([ADR-0025](../adr/0025-serve-artifacts-to-surfaces-through-the-control-plane.md)). See [Artifacts](https://dac-plane.github.io/dac-plane/use/surface-api/#artifacts).

## Building on dac-plane

### Adapter kit v0.4.0

The artifact store role adds `authorize_download`, behind the `artifact.download` capability: given the admitted manifest and the committed object version, the adapter answers with a presigned read of exactly that version. The S3 adapter offers it, presigning for five minutes. An adapter built with v0.3.0 keeps working: dac-plane serves records without it and answers downloads with `503 artifact-unavailable`.

```sh
go get github.com/dac-plane/dac-plane/adapterkit@v0.4.0
```

## Running dac-plane

### Two settings for downloads

`DAC_ARTIFACT_DOWNLOAD_ORIGINS` names the HTTPS origins dac-plane may fetch presigned reads from; any other URL an adapter returns is refused. `DAC_ARTIFACT_DOWNLOAD_CA_FILE` names the roots of those origins when they differ from the system roots. Without the first, records are served and downloads answer `503 artifact-unavailable`. The reference stacks set it to `https://artifact-store:8443`. See the [configuration reference](https://dac-plane.github.io/dac-plane/reference/configuration/).

## Upgrading

Follow ADR-0011. The schema stays at 18, so no migration runs:

1. Set `DAC_ARTIFACT_DOWNLOAD_ORIGINS` for `serve` to your artifact store's origin, and `DAC_ARTIFACT_DOWNLOAD_CA_FILE` if its certificate is not signed by the system roots. The reference Compose files in the v0.4.0 bundle already set it.
2. Roll every `serve` replica and every adapter to the v0.4.0 digests. Downloads work once both `serve` and the S3 adapter run v0.4.0.

Roll back by restoring the v0.3.0 digests; nothing in the database changes.

This path runs in CI on every pull request once the upgrade test's pin advances to v0.4.0.

### Breaking changes

None. The Surface API stays v1; its document moves to 1.3.0 with additions only.

### Notable changes

- Downloads are logged with tenant, task, artifact and principal. The presigned URL is never logged, and transport errors are stripped of it.

## Known limits

The limits in [the v0.3.0 notes](v0.3.0.md#known-limits) still apply.

- **Downloads are not part of the live provider qualification.** The artifact store stack test downloads a committed artifact through SeaweedFS and the S3 adapter on every pull request, but the live Codex and E2B qualification does not fetch one.
- **Downloads cost dac-plane bandwidth.** Bytes are relayed, never buffered whole; the pilot's artifacts are reports and diffs.
- **A store that keeps a read waiting for thirty seconds ends the download.** Only time spent waiting on the store counts, so a slow client is not cut short.
